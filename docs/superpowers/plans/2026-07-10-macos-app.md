# macOS Desktop App (Electron + SQLite) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Package NgốcKý as a self-contained macOS app: Electron shell boots the existing Express API in-process against a local SQLite database and serves the existing web build — no Docker, no Postgres, no server for the end user.

**Architecture:** New workspace `apps/desktop`. Electron main process: generates/loads local secrets, points `DATABASE_URL` at a SQLite file in `~/Library/Application Support`, applies schema DDL (generated at build time from a SQLite Prisma schema), imports the compiled API (`apps/api/dist`) and starts it on `127.0.0.1:<random port>`, serves the web `dist/` from the same Express app, then opens a BrowserWindow at that URL. Auth (JWT + httpOnly refresh cookie) works unchanged over localhost HTTP.

**Tech Stack:** Electron, electron-builder, Prisma with SQLite provider (pattern already proven by `apps/api/prisma/schema.test.prisma` + `src/test/client`), existing Express app and web build.

## Global Constraints

- **Depends on the module-system plan** (`2026-07-10-module-system.md`) being merged first: the desktop app relies on the setup wizard for first-run owner creation and on `AppSettingsService`. If executed before it, first-run must fall back to env-style seeding — do not build that fallback; just sequence the plans.
- **Do not fork the API.** `apps/api` code is shared between server and desktop; all desktop differences are injected via environment variables and the existing client-switch in `apps/api/src/config/database.ts`.
- SQLite schema file is `apps/api/prisma/schema.sqlite.prisma` (new, see Task 1) — generated from `schema.prisma` by extending `apps/api/scripts/generate-test-schema.mjs`, never edited by hand.
- Desktop binds the API to `127.0.0.1` only (never `0.0.0.0`).
- Node version: match repo (Node 20). Electron: latest stable major at implementation time.
- macOS signing/notarization is OUT OF SCOPE for this plan — produce an unsigned `.dmg` that runs locally (right-click → Open). A follow-up plan covers signing.
- Auto-update: out of scope (YAGNI v1).
- Commit after each task, `feat:` prefix.

**Steps:**

- [ ] **Step 1: Refactor `index.ts`:**

```ts
import app from './app';
import { config } from './config/env';
import { prisma } from './config/database';
import { AuthService } from './services/auth';

export async function startServer(options: { port?: number; host?: string; serveWebDir?: string } = {}) {
    await prisma.$connect();
    console.log('✅ Database connected');
    await AuthService.seedOwner(); // already a no-op without OWNER_EMAIL after module-system plan

    if (options.serveWebDir) {
        const express = require('express');
        const path = require('path');
        app.use(express.static(options.serveWebDir));
        // SPA fallback for non-API routes
        app.get(/^(?!\/api\/).*/, (_req: any, res: any) => res.sendFile(path.join(options.serveWebDir!, 'index.html')));
    }

    const host = options.host ?? '0.0.0.0';
    const port = options.port ?? parseInt(config.APP_PORT);
    return new Promise<{ port: number; close(): Promise<void> }>((resolve, reject) => {
        const server = app.listen(port, host, () => {
            const actual = (server.address() as any).port;
            console.log(`🚀 NgocKy API running on port ${actual} (${config.NODE_ENV})`);
            resolve({ port: actual, close: () => new Promise((r) => server.close(() => r(undefined))) });
        });
        server.on('error', reject);
    });
}

if (require.main === module) {
    startServer().catch((err) => {
        console.error('❌ Failed to start:', err);
        process.exit(1);
    });
}
```

Note: SPA fallback must be registered **after** all `/api` routes (it is — `app` arrives fully configured) but **before** the error handler catches 404s — check how `app.ts` ends; if it registers a 404/error handler, `serveWebDir` middleware must be inserted before it. If `app.ts` ends with `app.use(errorHandler)`, restructure minimally: export a `mountStatic(dir)` helper from `app.ts` that inserts the static middleware just before the error handler, or simplest — in `app.ts`, read `config.SERVE_WEB_DIR` (new optional env via `env.ts`) and mount static there directly, and drop `serveWebDir` from `startServer`. **Pick the `env.ts` approach** — desktop sets `SERVE_WEB_DIR` env var; no signature juggling.

```ts
import { app, BrowserWindow, dialog } from 'electron';
import path from 'path';
import fs from 'fs';
import crypto from 'crypto';

function resourcePath(...p: string[]) {
    // In dev, repo root; in packaged app, Resources dir
    return app.isPackaged
        ? path.join(process.resourcesPath, ...p)
        : path.join(__dirname, '..', '..', '..', ...p);
}

function loadOrCreateSecrets(userData: string) {
    const file = path.join(userData, 'secrets.json');
    if (fs.existsSync(file)) return JSON.parse(fs.readFileSync(file, 'utf8'));
    const secrets = {
        JWT_SECRET: crypto.randomBytes(32).toString('hex'),
        JWT_REFRESH_SECRET: crypto.randomBytes(32).toString('hex'),
    };
    fs.writeFileSync(file, JSON.stringify(secrets), { mode: 0o600 });
    return secrets;
}

async function applySchema(dbFile: string) {
    // ponytail: full DDL re-apply guarded by schema hash; real migrations when schema evolves post-v1
    const ddl = fs.readFileSync(resourcePath('api', 'prisma', 'sqlite-init.sql'), 'utf8');
    const hash = crypto.createHash('sha256').update(ddl).digest('hex');
    const hashFile = dbFile + '.schema';
    const fresh = !fs.existsSync(dbFile);
    if (!fresh && fs.existsSync(hashFile) && fs.readFileSync(hashFile, 'utf8') === hash) return;
    if (!fresh) {
        // schema changed since last run — v1 policy: refuse rather than corrupt
        dialog.showErrorBox('Upgrade required', 'Database schema changed. Back up your data file and delete it to continue: ' + dbFile);
        app.exit(1);
        return;
    }
    const { prisma } = require(resourcePath('api', 'dist', 'config', 'database.js'));
    for (const stmt of ddl.split(/;\s*\n/).map((s) => s.trim()).filter(Boolean)) {
        await prisma.$executeRawUnsafe(stmt);
    }
    fs.writeFileSync(hashFile, hash);
}

async function boot() {
    const userData = app.getPath('userData');
    fs.mkdirSync(userData, { recursive: true });
    const dbFile = path.join(userData, 'ngocky.db');
    const secrets = loadOrCreateSecrets(userData);

    Object.assign(process.env, {
        NODE_ENV: 'production',
        DB_PROVIDER: 'sqlite',
        DATABASE_URL: 'file:' + dbFile,
        SERVE_WEB_DIR: resourcePath('web'),
        CORS_ORIGIN: 'http://127.0.0.1',
        ...secrets,
    });

    await applySchema(dbFile);
    const { startServer } = require(resourcePath('api', 'dist', 'index.js'));
    const { port } = await startServer({ port: 0, host: '127.0.0.1' });

    const win = new BrowserWindow({
        width: 1280,
        height: 840,
        title: 'NgốcKý',
        webPreferences: { contextIsolation: true },
    });
    await win.loadURL(`http://127.0.0.1:${port}/`);
}

app.whenReady().then(boot).catch((err) => {
    dialog.showErrorBox('Startup failed', String(err?.stack || err));
    app.exit(1);
});
app.on('window-all-closed', () => app.quit());
```

Adjust to reality while implementing: (a) `env.ts` may **require** vars this env object doesn't set (e.g. `OWNER_EMAIL`?) — read `env.ts` and satisfy or relax as the module-system plan already made owner vars optional; (b) `CORS_ORIGIN` must accept the dynamic port — check how `app.ts` configures cors; if it does exact-match origin, set `CORS_ORIGIN` after the port is known **before** requiring `app`, i.e. move `startServer` require after computing port — since port is random, simplest correct fix: in `app.ts` CORS config, also allow any `http://127.0.0.1:*` origin when `DB_PROVIDER === 'sqlite'`. Same-origin requests (web served by same Express) mostly bypass CORS anyway — verify and simplify.

```yaml

productName: NgocKy

  output: release
files:
  - dist/**
extraResources:
  - from: ../api/dist
    to: api/dist
```

Critical detail: the API's `require('../generated/sqlite-client')` resolves relative to `api/dist/config/database.js` at runtime → generated client must land at `api/dist/generated/sqlite-client` in Resources, AND its native engine (`libquery_engine-darwin-arm64.dylib` inside the generated client dir) must be included — electron-builder `extraResources` copies files as-is (no asar), so this works. Also the API's own `node_modules` (express, zod, …) are NOT in `api/dist`. Two options; take B:
  - A) bundle API with a bundler — more moving parts.
  - B) `extraResources` also copies the API workspace `node_modules` — in an npm-workspaces repo dependencies are hoisted to root `node_modules`. So copy from root: `- from: ../../node_modules  to: api/node_modules` and set `NODE_PATH` — brittle. **Better:** before packaging, run `npm run bundle:api` (new script) that does `esbuild apps/api/src/index.ts --bundle --platform=node --format=cjs --outfile=apps/desktop/bundled/api.js --external:../generated/sqlite-client --external:.prisma` — one file, only the prisma generated client stays external. Add `esbuild` as a desktop devDependency. Then `extraResources` ships `bundled/api.js` + generated client + engine + sqlite-init.sql, and `main.ts` requires `resourcePath('api.js')`.

  Implement option B (esbuild bundle). Adjust `main.ts` `resourcePath` calls accordingly (`api.js`, `sqlite-init.sql`, `web/`). The `applySchema` prisma require then comes from the bundle: export `prisma` from the bundle too (`index.ts` already imports it; add `export { prisma } from './config/database';` to `apps/api/src/index.ts`).
