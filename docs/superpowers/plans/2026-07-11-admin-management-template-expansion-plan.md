# Admin Management, Agent Providers, and Template Expansion Implementation Plan

> **For agentic workers:** Execute this plan task-by-task. Use test-first development where a behavioral contract changes. Commit after every task with the specified message. Do not expose a template in the create-page UI until its entire task is complete.

**Goal:** Move application-wide settings into Admin pages, add secure multi-provider agent configuration, centralize custom-page lifecycle, and expand page instances to every current module template.

**Design:** `docs/superpowers/plans/2026-07-11-admin-management-template-expansion-design.md`

**Depends on:** Completed `docs/superpowers/plans/2026-07-10-module-system.md`

**Tech stack:** Existing React/Vite, Express, Prisma/PostgreSQL, generated SQLite test schema, Zod, React Query, Zustand, OpenAI SDK; add the official Anthropic TypeScript SDK.

## Global Constraints

- Existing built-in routes and records remain the `instanceId = null` partition.
- Never edit `apps/api/prisma/schema.test.prisma` manually. It is generated by `apps/api/scripts/generate-test-schema.mjs`.
- After every Prisma change, run `npm run db:generate` and the focused API tests before the full suite.
- All API inputs use Zod and the existing `validate()` middleware.
- All environment access goes through `apps/api/src/config/env.ts`.
- Credentials are encrypted, write-only, and never logged or returned.
- OWNER-only checks must exist in the API even when the frontend route is hidden.
- Page template and group compatibility is enforced server-side.
- Page rename never changes `slug`.
- Update routes never permit moving a record between page instances.
- Parent/child modules derive child partition from the parent root record.
- Custom endpoints are untrusted network input and must pass SSRF validation on every request and redirect.
- Keep commits focused. Do not combine unrelated refactors with a template task.

## Verification Commands

Use these throughout:

```bash
npm run db:generate
cd apps/api && npx vitest run <focused-test-file>
cd apps/api && npm test
cd apps/api && npm run lint
cd apps/web && npm test
cd apps/web && npm run build
git diff --check
```

The current API `build` script masks TypeScript errors with `|| true`; use `npm run lint` as the required TypeScript gate.

## Suggested Execution Batches

To keep deployment risk controlled:

1. Tasks 1-7: Agent Settings.
2. Tasks 8-11: Application Management and shared template infrastructure.
3. Tasks 12-15: Ideas and flat Family templates.
4. Tasks 16-20: Hierarchical and Hobby templates.
5. Tasks 21-25: Cross-cutting integration, cleanup, and deployment.

Each batch should be deployable and reversible independently. Keep unavailable templates hidden behind the server-side catalog until their batch is complete.
